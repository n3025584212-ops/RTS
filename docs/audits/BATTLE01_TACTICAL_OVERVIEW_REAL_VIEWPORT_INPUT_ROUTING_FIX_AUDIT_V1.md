## 1. Original blocker

UPSTREAM_QA_GATE=RERUN_QA_GATE_BATTLE01_PRE_BATTLE_STAGING_V1=REWORK_REQUIRED  
ORIGINAL_BLOCKER=TACTICAL_OVERVIEW_DIRECT_HANDLER_SMOKE_DID_NOT_PROVE_REAL_VIEWPORT_GUI_WORLD_INPUT_ROUTING

The existing Tactical Overview Camera3D mapping remains unchanged and correct. The blocker was event priority: `Battle3DInput` processed mouse events in `_input(event)`, which runs before Control GUI dispatch. A real minimap click could therefore reach world selection/placement/command handling before `BattleMinimap._gui_input()` had a chance to consume it.

## 2. Input routing fix

PRODUCTION_FILE=scripts/battle01/battle_3d_input.gd

OLD_WORLD_INPUT_HANDLER=_input  
NEW_WORLD_INPUT_HANDLER=_unhandled_input  
GUI_INPUT_PRIORITY=CONTROL_GUI_INPUT_THEN_WORLD_UNHANDLED_INPUT  

The existing world interaction implementation is preserved. Only its SceneTree input phase changed. Interactive Controls can now receive `_gui_input()` and call `accept_event()` before any mouse event reaches the 3D world handler.

The existing staging-panel point check remains only as defense-in-depth; it is no longer the sole protection for HUD interaction.

## 3. Runtime observability hook

`Battle3DInput` now exposes a read-only world input serial and active-pointer-state query for runtime testing:

- `get_world_input_serial_for_test()`
- `is_world_pointer_interaction_active_for_test()`

These hooks do not issue commands or modify gameplay. They allow the real Viewport smoke to prove that GUI-owned Tactical Overview / staging button events did not enter the world handler.
